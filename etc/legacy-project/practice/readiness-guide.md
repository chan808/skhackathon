# AI 활용 준비 상태를 확인하는 실전형 연습

개념 문제를 맞힌 뒤에는 AI 답변의 오류를 제한된 시간 안에 찾아서 수정할 수 있는지 확인해야 한다. 이 연습은 CSV의 여러 조건, 문서 효력과 단위, 잘못된 평가 결론을 한 번에 판단하는 세 사례로 구성했다. 코딩 없이 메모와 계산기로 풀 수 있으며, 정답을 읽고 이해하는 것과 직접 판단해 제출하는 능력을 구분한다.

모든 데이터·규정·AI 보고서는 창작한 합성 자료다. 공식 기출·복원·예상문항이 아니며, 실제 시험 형식·시간·점수·질문 제한을 재현한다고 볼 수 없다. 실제 응시에서는 공식 도구 사용 규정을 우선한다.

## 문제와 풀이를 분리해서 사용하기

문제는 `readiness-cases.json`에 있다. 처음에는 각 사례의 `context`, `data`, `documents`, `tasks`만 읽는다. `answer_key`와 `scoring_rubric`는 답안을 저장한 뒤 확인한다. 모든 원자료가 문제 안에 있으므로 웹 검색이나 데이터 다운로드가 필요하지 않다.

첫 시도는 CLI로 시작하면 정답 키와 채점 기준을 화면에서 숨길 수 있다. JSON 파일 전체를 먼저 열면 풀이를 미리 볼 수 있으므로 독립 풀이 점검에는 CLI가 편하다.

```powershell
.\.venv-study\Scripts\python.exe -m practice.readiness start --case RC01
```

답은 여러 줄로 작성하고 `/done`으로 저장한다. `/prompt`는 질문 초안을 기록하며 AI를 호출하거나 답을 생성하지 않는다. 실제 AI를 사용한 연습과 질문 초안만 작성한 연습을 구분한다. 저장한 기록은 `practice.readiness review`로 기준 풀이와 비교하고 자가 평가할 수 있다.

| 사례 | 연습하는 판단 | 권장 연습 시간 |
| --- | --- | --- |
| RC01 | 예상 순이득을 최대화하는 정수 선택, 예산과 시간 제약, 생산량 가중 비율 | 18분 |
| RC02 | 규정 효력과 적용 대상, MB와 MiB, 연속 초과와 승인 상태 | 18분 |
| RC03 | 혼동행렬·비용, 평가 누수, 생산 구성 변화, 인과 주장 감사 | 20분 |

시간과 최대 AI 요청 3회는 이 폴더의 연습 장치다. 실제 플랫폼 제한을 뜻하지 않는다. 시간이 부족하면 한 사례만 완성하고, 어디서 시간이 쓰였는지 기록한다. 계산기나 스프레드시트를 써도 되며 코딩 환경을 새로 구성할 필요는 없다.

## 문제를 읽은 뒤 먼저 결정할 일

첫 3분은 AI 없이 읽는다. 다음 다섯 가지를 메모한다.

1. 최종적으로 무엇을 결정해야 하는가.
2. 그 결정의 목표, 분모, 단위와 적용 시점은 무엇인가.
3. 반드시 지켜야 하는 제약은 무엇인가.
4. 자료에서 확인되는 사실과 아직 확인되지 않은 가정은 무엇인가.
5. AI 답변을 어떤 계산이나 문서 조항으로 검증할 것인가.

그다음 첫 AI 요청을 사용한다. 원자료를 빠뜨리면 모델이 누락된 사실을 채워 넣을 수 있으므로 질문에 필요한 표와 문서를 함께 제공한다. 파일을 실제로 읽을 수 없는 도구에는 파일 경로만 주지 않는다.

## 세 번의 AI 요청을 쓰는 방법

첫 요청은 목적과 자료의 구조를 정리하고 계산 접근법을 확인하는 데 쓴다. 두 번째 요청에는 자신의 중간 결과를 주고 반례·누락된 제약·단위·문서 적용 오류를 찾게 한다. 세 번째 요청은 최종 답안에서 확인되지 않은 결론과 틀린 수치를 감사하게 한다.

각 사례에 `suggested_prompts` 세 개가 있지만 반드시 그대로 복사할 필요는 없다. 자신의 불확실한 부분을 구체적으로 전달하는 능력도 연습에 포함된다. 모델에게 정답을 한 번에 부탁한 뒤 세 번 표현만 바꾸는 방식은 계산과 근거 검증을 연습하기 어렵다.

AI 요청 한 번은 새로운 질문을 보내 응답을 받는 한 회로 기록한다. 같은 질문을 재전송하거나 추가 설명을 요구하면 한 회를 더 사용한 것으로 센다. 도구 내부의 호출 횟수나 공식 플랫폼의 카운트 방식에 대한 설명은 아니다.

AI 없이도 풀 수 있다. 그때는 자신이 만든 계산표와 근거를 동일하게 제출하고, 제한된 요청 연습을 했는지는 별도로 기록한다.

## 사례별 완료 조건

### RC01 예산과 점검 계획

최종 조합 이름만 적으면 부족하다. 시험별 순이득을 계산하고, 선택 조합이 예산·시간·라인·개수 제약을 만족하는지 보여준다. 다른 후보와 비교할 때 무엇을 최대화하는지 유지한다. 불량 감소 수가 가장 많은 조합과 비용을 뺀 순이득이 가장 큰 조합이 같다고 가정하지 않는다.

전체 비율은 모든 제품 수를 분모로 삼아 계산한다. 선택된 시험만의 불량률과 전체 생산의 불량률은 서로 다르다. 효과를 확인하기 전의 계획 숫자에는 기대값이라는 표현을 붙인다.

### RC02 문서와 파일 제출

게시일, 효력 기간, 적용 대상의 세 기준을 각각 확인한다. 최신 게시 자료라도 시행 전일 수 있다. 표시값을 반올림해 단위 한계를 판정하지 않고 원래 바이트 수를 비교한다.

연속 횟수는 로그 순서대로 계산하고, 한 번 기록된 검토 후보가 현재 해제됐는지는 별도로 판단한다. 파일 크기가 맞는 것과 운영상 자동 전송이 허용되는 것은 다른 조건이다. 최종 판단에는 적용 문서 ID와 조항을 남긴다.

### RC03 잘못된 AI 보고서

혼동행렬 계산은 AI 설명과 독립적으로 확인한다. 전체 정확도와 실제 불량을 잡는 비율을 구분하고, 가정한 비용으로 산술 비교를 한다. 평가 절차가 부적절한 모델의 비용 표를 실제 미래 성과로 확대하지 않는다.

누수의 종류를 하나로 뭉뚱그리지 않는다. 예측 시점 이후 정보, 같은 객체의 학습·평가 중복, 전처리 fit 범위, 최종 평가를 보며 반복 선택한 문제를 각각 찾아야 수정 방법도 정할 수 있다. 한 모델에 있는 문제를 자료에 없는 다른 모델에도 자동으로 적용하지 않는다.

전체 생산 비율이 달라지면 제품 구성도 확인한다. 설명 모델의 변수 기여도와 실제 공정 조건 변경의 효과는 같지 않다. 수정 보고서에는 검증된 계산, 근거가 부족한 주장, 다음 검증을 구분한다.

## 제출할 답안과 기록

각 사례에 다음 내용을 남긴다. 문장 길이를 늘리기보다 계산표와 조항 연결을 정확하게 작성한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 결정 | 선택 계획·허용 여부·배포 판단 |
| 계산 | 공식, 분모, 단위, 중간값, 최종값 |
| 근거 | 원자료 행 또는 문서 ID와 조항 |
| 검증 | 독립 재계산, 경쟁 후보, 반례, 경계값 확인 |
| 한계 | 기대값·미검증 원인·평가 타당성의 범위 |
| 다음 행동 | 결정을 확정하기 위해 필요한 확인 한 가지 |
| 사용 기록 | 소요 시간, AI 요청 수, 자신의 초기 판단과 수정 내용 |

답안은 정답 공개 전에 저장한다. 정답을 보고 바꾼 내용은 별도로 구분해 학습 메모로 남긴다. 답안을 짧게 쓰라는 제한도 각 문제의 자체 연습 조건이다.

## 자기 평가 기준

각 사례는 20점이며 JSON의 세부 기준에 따라 자신이나 다른 사람이 평가한다. 숫자가 일부 맞는지, 근거가 연결되는지, 판단이 제약과 일치하는지를 따로 확인한다. **명령 실행이나 JSON 파싱의 성공은 자유 서술 답안의 정확성을 자동으로 검증하지 않는다.** AI에게 평가를 맡기더라도 원자료와 정답 키를 사람이 대조해야 한다.

총점 60점은 이 세 연습에서의 완성도다. 실제 대회의 통과 가능성·합격 점수·공식 평가 가중치로 해석하지 않는다. 점수만 적지 말고 `critical_errors`의 중대한 오류가 남아 있는지도 확인한다. 제약 위반 계획, 효력 없는 규정 적용, 크기 경계 판정 오류, 누수 평가의 배포 근거 사용, 근거 없는 원인 확정이 남으면 해당 항목부터 다시 연습한다.

준비 상태를 판단할 때는 다음 증거를 우선한다.

| 우선순위 | 준비를 보여주는 증거 | 보완이 필요한 모습 |
| --- | --- | --- |
| 1 | 원자료에서 분모·단위·시점을 정하고 독립 계산으로 AI 오류를 찾음 | 모델의 수치를 그대로 복사하거나 정답을 본 뒤에만 설명 |
| 2 | 서로 충돌하는 조건과 자료를 해결하고 선택하지 않은 후보의 이유를 설명 | 최신 문서·가장 높은 점수·가장 큰 비율을 자동 선택 |
| 3 | 제한된 질문에서 자신의 중간 결과와 구체적 검증 요청을 전달 | 매번 정답 전체를 다시 요청하고 반례 검토를 생략 |
| 4 | 근거에 없는 부분을 보류하고 다음 확인을 정함 | 정확도·상관·전후 차이를 운영 성과나 인과로 확대 |
| 5 | 시간 안에 검토 가능한 짧은 결과를 저장 | 계산은 맞지만 결론과 근거가 흩어져 제출 불가 |

한 번 통과한 뒤에는 숫자·단위·효력 날짜 하나를 바꿔 같은 판단이 유지되는지 확인한다. 답안 문구를 외우기보다 어떤 조건이 바뀌면 결론도 바뀌는지 설명한다. 틀린 문제를 고치는 동안 새 데이터셋이나 프레임워크를 추가할 필요는 없다.
