# 에이전트 실행 구조 연습

이 예제는 1차 이후에 선택적으로 살펴볼 개발 자료다. 첫 준비는 공식 체험, AI 기초, 자료 해석과 검증이다. 별도 에이전트 앱이 필요한 상황을 이해하려면 여기서 도구 계약, 실행 결과, 반복 종료를 확인한다.

## 추가 계정 없이 흐름 보기

```powershell
.\.venv-study\Scripts\python.exe -m examples.agent_loop
```

기본 모드는 **스크립트로 정해 둔 응답을 재생하는 오프라인 시연**이다. 실제 LLM이 추론하거나 도구를 선택하지 않는다. 따라서 이 시연의 성공은 실제 모델·에이전트의 성능 증거가 아니다. 실행 기록은 `reports/agent-loop-offline.json`에 저장된다.

원본 합성 문서를 읽고, 온도를 변환하고, 연속 초과 조건을 계산하고, 최종 결과를 독립 검사하는 흐름을 보여준다. 각 도구는 실제로 실행되고 결과가 다음 단계의 입력에 들어간다. 모델 자리에 재생기를 둬 네트워크나 API 키 없이 구조를 확인한다.

| 구성 | 담당하는 일 |
| --- | --- |
| TOOLS | 이름 인수 설명을 포함한 도구 계약 |
| dispatch | 허용된 기능과 인수를 검사하고 실제 계산 |
| backend | 다음 도구 호출 또는 최종 응답 생성 |
| run | 모델 출력과 도구 결과를 이어가며 반복 한도 관리 |
| agent_check | 한 합성 사례의 수치 근거 조치 범위 검사 |

최대 모델 단계는 6회, 도구 호출은 8회로 제한한다. 잘못된 도구 이름과 인수는 실행하지 않고 오류로 돌려준다. 파일 읽기는 정해둔 합성 자료 하나만 제공한다. 이 예제에는 임의 터미널 실행·메일 전송·장비 제어 기능이 없다.

`contract_passed`는 한 합성 사례의 최종 값과 조건이 검사에 맞는다는 뜻이다. 실제 도구 호출·인수·성공·관찰은 `trace`에서 따로 확인한다. 최종 값이 맞다는 이유만으로 모델이 도구를 실제로 실행했다거나 근거 선택 과정이 올바랐다고 판정하지 않는다.

## 실제 모델을 연결하는 선택 경로

`ResponsesBackend`는 OpenAI Responses API의 function calling 흐름을 사용하는 연결 초안이다. 실제 모델을 쓰려면 `OPENAI_API_KEY`와 사용할 `OPENAI_MODEL`을 직접 지정하고 `--live`로 명시적으로 실행한다. `.env` 파일은 자동으로 읽지 않으며 키를 코드·로그에 넣지 않는다. 이번 준비 작업에서는 실제 API 요청을 하지 않았으므로 계정 권한, 선택 모델의 기능, 네트워크, 실제 응답 품질은 미검증 상태다.

실제 요청에는 API 사용량이 발생할 수 있다. 기본 시연과 1차 학습에는 이 경로가 필요하지 않다. 실행을 선택하기 전 계정에서 이용 가능한 모델과 비용을 확인한다. 모델 이름을 코드가 임의로 최신 모델로 바꾸지는 않는다.

```powershell
# OPENAI_API_KEY와 OPENAI_MODEL을 본인 환경에 준비한 경우에만 실행
.\.venv-study\Scripts\python.exe -m examples.agent_loop --live
```

실제 모델 모드도 같은 세 도구와 호출 한도를 사용한다. 결과는 `reports/agent-loop-live.json`으로 저장한다. 한 과제를 통과해도 일반적인 정확성·보안·신뢰성 또는 대회 준비 완료를 보장하지 않는다.

공식 프로토콜은 [Function calling](https://developers.openai.com/api/docs/guides/function-calling)에서 확인한다. `store=false`로 상태를 재전달할 때 reasoning 등의 응답 항목도 보존하는 원칙은 [Reasoning models](https://developers.openai.com/api/docs/guides/reasoning)에 설명돼 있다. SDK를 도입할 때 실행·도구·상태의 책임을 비교하려면 [Agents SDK](https://developers.openai.com/api/docs/guides/agents/sdk)를 참고한다.

## 직접 해볼 변경

오프라인 응답에서 현행 규정을 옛 규정으로 바꾸면 최종 검사에서 실패하는지 본다. 모델이 허용하지 않은 도구를 요청하게 하면 실행되지 않고 오류가 반환되는지 확인한다. 끝없이 같은 도구를 요청하게 하면 호출 한도에서 멈추는지 확인한다. 이 변경은 실행 구조를 배우는 실습이며 실제 시험 감독·권한을 우회하는 연습이 아니다.

단순한 입력에서 계산이 정해져 있다면 고정 코드가 기준 풀이로 충분하다. 입력의 모호함·자료 충돌·다양한 도구 선택이 반복돼야 할 때 모델의 판단을 추가하고, 어떤 오류가 생기는지 평가한다.
