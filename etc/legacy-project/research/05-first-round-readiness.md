# 1차 예선 준비도 점검과 남은 보완 과제

2026년 10월 14일 KST 기준. **조사 자료를 조금 읽은 것만으로 1차 준비가 완벽해졌다고 판단할 수 없다.** 현재 확인된 것은 조사와 연습 도구가 준비돼 있다는 사실이다. 본인이 처음 보는 자료를 제한된 시간 안에 해석하고, AI의 제안을 검증하고, 정확한 답으로 정리할 수 있는지는 직접 수행한 기록으로 확인해야 한다.

아래 준비도 기준은 이 폴더를 위한 학습 기준이다. 대회 합격선·실제 배점·문항 수·시간을 추정한 것이 아니다. 실패한 항목을 찾아 남은 시간의 학습을 좁히는 데 사용한다.

## 초기 점검에서 준비됐던 것과 이후 확인할 것

점검 대상은 10월 13일에 만든 기본 조사와 연습 환경이다. `reports/verification-2026-10-13.json`의 9개 테스트 통과는 도구의 채점·데이터 처리 동작을 확인한 결과이며 응시자의 시험 성적이 아니다. 개인 수행 기록은 공개 저장소에서 제외하므로 직접 수행한 결과로 준비도를 확인한다. 최신 학습 순서는 [학습 경로](../LEARNING-PATH.md), 합격 공지와 상세 메일 확인은 [공지 조사](07-notice-and-open-questions.md)를 따른다.

| 항목 | 현재 상태 | 준비 완료로 볼 수 없는 이유 |
|---|---|---|
| 공식 행사·플랫폼 조사 | 확보 | 개인 안내의 구체 규칙과 다를 수 있음 |
| 기초 개념 40문항 | 확보 | 객관식 정답 선택과 설명·실전 적용은 다름 |
| 합성 CSV와 SQL 교차검증 | 동작 확인 | 기준 풀이를 읽는 것과 독립 풀이가 다름 |
| 문서·코드 검증 미션 | 확보 | 개인별 완료 시간·오류·수정 이력 미확인 |
| 공식 체험의 본인 수행 | 개인별 확인 필요 | 로그인 이후 화면 조작·질문 선택 경험 필요 |
| 개인 응시 규칙 | 초대 수신 후 개인별 확인 | 시간·문항 수를 받은 뒤에도 감독·도구·저장 조건은 별도 확인 |
| 낯선 변형 과제 수행 | 미확인 | 반복 문제를 기억하는 효과를 분리하지 못함 |

기존 퀴즈는 기본 오류를 발견하는 입문 진단에 적합하다. 다수 문항의 오답은 “항상 정확하다”, “검증을 생략한다”, “무한 재시도한다”처럼 쉽게 배제된다. 높은 점수를 받아도 비슷하게 그럴듯한 대안 중 하나를 고르는 판단, 여러 문서의 충돌 해소, 계산과 답안 작성, 시간 관리까지 검증하지는 못한다. 이는 문항을 직접 검토한 판단이며 공식 시험 난이도에 관한 주장과 다르다.

## 공식 설명으로 좁힌 학습 범위

프로그래머스가 작성한 세미나 후기는 지식평가를 원리·한계·윤리·보안의 이해, 활용평가를 AI와 실무 과제를 해결하는 능력, 전문평가를 과정 기록을 통한 통제·재현성 확인으로 설명한다. 일반 플랫폼의 영역 설명이며 SK하이닉스 1차의 구체 조합표는 아니다. [프로그래머스 공식 세미나 설명](https://community.programmers.co.kr/post/14224)

공식 기업교육 페이지는 문제 정의·AI 협업·결과 검증·책임 관리를 4P로 제시한다. 결과 기준에는 요구 충족·데이터 정확성·논리·업무 활용, 과정 기준에는 구조화·전략·교차 검토·개선·보안 준수가 있다. 해당 페이지의 점수 산정 예시는 **이번 대회 배점으로 적용하지 않는다.** [프로그래머스 공식 4P 설명](https://programmers.co.kr/b2b-education)

이 범위를 준비 행동으로 옮기면 다음과 같다. 아래 예시는 자체 제작 학습 상황이며 공식 샘플이나 기출의 복제가 아니다.

| 학습 영역 | 직접 해봐야 할 행동 | 확인할 흔적 |
|---|---|---|
| 원리·한계 | AI가 답을 만들 때 생기는 오류를 자신의 사례로 설명 | 낮은 temperature와 사실 정확성의 차이 설명 |
| 문제 정의 | 무엇을 계산·비교·결정하는지 먼저 쓰기 | 기간·대상·분모·예외·답안 형식 |
| AI 협업 | 필요한 자료만 고르고 구체적인 역할 주기 | 질문 목적·선택 자료·불필요한 자료 배제 이유 |
| 결과 검증 | AI와 다른 방식으로 숫자·근거 확인 | 수작업 표본·계산식·문서 버전·반례 |
| 책임 관리 | 개인정보·권리·도구 권한을 판단 | 입력을 제외한 정보와 그 이유, 허용 범위 |
| 개선 | 오류의 원인을 찾아 최소 수정 | 첫 결과·지적한 오류·수정 후 재검증 |

공식 리터러시 글도 강의 이수나 도구 사용만으로 역량 향상을 판단하지 않고, 과제 수행과 재측정을 권한다. 같은 문제 반복은 기억 효과를 만들 수 있어 변형 문제를 사용하라고 설명한다. [프로그래머스 리터러시 교육 설명](https://programmers.co.kr/ai-assessment/insight/ai-literacy-training)

## 네 가지 준비도 확인

각 항목을 “읽음”으로 체크하지 않고 직접 수행한 결과를 기록한다. 하나라도 핵심 조건이 미확인이라면 해당 부분을 먼저 해결한다. 모두 확인돼도 실제 합격을 보장하는 기준은 아니다.

### 개인 안내와 환경

`templates/exam-preflight.md`에 본인 배정일·시작·입장 마감·시험 길이, 허용 도구, 감독 조건, 저장·최종 제출, 장애 절차를 기록한다. 시험 링크에 개인 토큰이 있으면 이 폴더에 그대로 붙여 넣지 않는다. 필요한 경우 도메인과 일반적인 접근 경로만 남긴다.

공식 체험에서 파일을 읽는 위치, AI에 자료를 전달하는 방식, 답을 쓰는 칸, 화면 이동을 확인한다. 로그인 이후 화면은 본인이 사용한다. 공개 체험과 실전 감독·시간 조건의 차이는 [기존 대회 조사](01-event.md)에 정리돼 있다. [공식 응시자 체험](https://programmers.co.kr/ai-assessment/preview)

확인할 결과는 “로그인 성공” 하나가 아니다. 자료를 읽고 답을 입력하는 데 걸리는 시간을 알고, 실전 안내의 중요한 빈칸이 없어야 한다. 감독 요구가 있을 때 사용할 PC·브라우저·권한을 개별 안내에 맞춰 확인한다.

### 개념을 설명하는 능력

기존 40문항을 먼저 풀되 채점 전에 각 답의 이유를 짧게 말하거나 쓴다. “정답 보기만 기억했다”, “다른 보기가 틀린 이유를 모른다”, “자신의 사례를 못 든다”를 별도 표시한다. 총점만으로 정리하지 않는다.

다음 여섯 주제는 보기 없이 설명한다. 이는 핵심 개념을 확인하기 위한 선정이며 실제 출제 목록이 아니다.

1. 토큰·문맥 한도와 사실 검증의 관계.
2. 프롬프트 예시와 모델 재학습의 차이.
3. RAG에서 검색과 최종 답의 검증을 나누는 이유.
4. JSON 형식 준수와 의미·수치 정확성의 차이.
5. 도구 호출 요청과 실제 실행의 차이.
6. 개인정보·비공개 자료를 외부 AI에 보내기 전 확인할 조건.

틀린 주제는 정의를 다시 읽은 뒤 다른 상황으로 설명한다. 원래 문항을 그대로 다시 맞히는 것만으로 보완 완료 처리하지 않는다.

### 자료와 계산을 검증하는 능력

기준 결과를 열지 않고 낯선 자료를 하나 푼다. 연습에 사용할 시간은 스스로 정하며 실제 시험시간으로 부르지 않는다. 다음 유형 중 아직 수행하지 않은 것을 선택한다.

| 유형 | 학습 상황 | 반드시 확인할 것 |
|---|---|---|
| 수량·비율 | 검사 수량이 다른 두 집단 비교 | 분모와 가중치, 중복·결측 처리 |
| 비용 | 월·연 요금과 이용 기간 비교 | 기간 정합성·필수 비용·반올림 |
| 규정 | 새 규정과 폐기 규정이 함께 제공 | 효력일·예외·규정과 데이터 연결 |
| 조건 부족 | 필요한 기록이 일부 빠짐 | 단정 대신 확인 불가와 필요한 자료 |

마지막에는 답의 숫자·단위·근거와 “이 자료로 알 수 없는 것”을 따로 쓴다. AI의 제안이 맞아 보이더라도 최소 하나의 독립 계산이나 반례로 확인한다. 답을 보고 오류를 수정했다면 첫 시도와 수정 시도를 구별한다.

### 제한된 질문으로 협업하는 능력

평소 사용하는 AI가 있다면 **자체 연습 자료만** 사용해 질문 예산을 스스로 정하고 푼다. 질문 수·자료량·시간 제한은 훈련 조건이며 대회의 확정 규칙이 아니다. AI가 없다면 미리 작성된 잘못된 제안을 읽고 반박·수정하는 방식으로 판단 연습을 한다. 실제 모델 응답 대기·편차를 경험한 것과는 구별해 기록한다.

각 질문에는 목적이 있어야 한다. 첫 질문 전에 문제를 읽고 필요한 자료를 선택한다. 이후에는 이미 확인한 내용을 반복해서 묻기보다 불확실한 계산·예외·근거를 해결한다. 마지막 답은 AI 대화 전체를 복사하는 대신 요구한 형식과 확인된 내용으로 정리한다.

공식 체험의 제한을 확인한 뒤 사용할 대화를 배분한다. 이미 사용한 체험 횟수가 초기화된다고 가정하지 않는다. 정확한 제한과 체험·실전 차이는 해당 페이지 FAQ를 따른다. [프로그래머스 공식 체험 FAQ](https://programmers.co.kr/ai-assessment/preview)

## 준비도 판단 기록

임의의 정답률을 대회 합격선으로 설정하지 않는다. 다음 네 칸에 구체적 결과를 적으면 무엇이 남았는지 판단할 수 있다.

| 확인 | 남길 결과 | 보완이 필요한 신호 |
|---|---|---|
| 규칙·환경 | 개인 안내 요약과 화면 확인 | 허용 도구·시각·최종 제출이 불명확 |
| 개념 | 보기 없는 설명과 변형 사례 | 정답 암기만 가능, 핵심 용어 혼동 |
| 활용 | 낯선 과제의 첫 풀이·시간·검증 | 기준 답을 봐야 진행, 단위·예외 누락 |
| 협업 | 질문·채택·기각·수정 기록 | 첫 답 그대로 제출, 근거 없는 결과 승인 |

점검 이후에는 세 가지 상태를 구분한다. **학습 자료 준비**는 도구와 문서 확보, **기본기 확인**은 개념 설명과 독립 계산, **응시 흐름 확인**은 본인 안내를 반영한 환경·과제·제출 연습이다. 현재 기본 세팅의 검증 기록만으로는 첫 상태까지만 확인할 수 있다.

## 10월 14일부터의 우선순위

오늘은 공식 체험과 개인 안내, 보기 없는 개념 설명, 낯선 활용 과제 한 개를 끝낸다. 다음 날은 오늘 실패한 두 항목을 집중 보완하고 다른 조건의 과제로 다시 확인한다. 배정 전날은 새로운 프레임워크보다 파일 처리·질문 선택·답 입력·최종 제출 흐름을 정리한다.

웹개발 경험을 활용할 때에도 코드 작성 자체를 목표로 두지 않는다. 표와 규정의 조건을 명확히 하고, 잘못된 결과를 재현하고, 독립 계산으로 확인하는 능력을 먼저 보여준다. 현재 공개 정보만으로 외부 IDE나 로컬 코드가 실전에서 허용된다고 가정할 수 없다.

이번 재확인에서 읽은 공개 행사 페이지와 플랫폼 글에는 SK하이닉스 개인별 시험 길이·정확한 문항 구성·외부 도구 허용표를 확정할 자료가 없었다. 10월 13일·14일 공개 검색과 공식 글 목록도 확인했지만 특정 참가자에게 발송된 안내를 대신하지 못한다. **본인에게 온 응시 안내가 남은 준비를 구체화하는 가장 중요한 자료다.** [공식 대회 페이지](https://skhynix-hackathon.com/ai-2026), [공식 플랫폼 글 목록](https://programmers.co.kr/ai-assessment/insight)
