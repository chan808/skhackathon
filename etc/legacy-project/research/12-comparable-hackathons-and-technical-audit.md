# 유사 AI 해커톤 조사와 프로젝트 기술 준비 점검

2026년 10월 15일 KST 기준. **현재 프로젝트는 오프라인 개념 학습과 자료 검증 연습을 시작하기에 충분하다. 실제 AI 결과물의 성능과 참가자의 제한 시간 수행 능력까지 검증된 완전한 준비 상태는 아니다.** 새 가상환경을 만들고 기존 39개 테스트를 통과했으며, 이동용 ZIP 생성기의 Git 탐색 결함을 수정한 뒤 43개 테스트를 통과했다. 별도 경로에서 새 환경을 만드는 재현 검사도 통과했다. 실행 증거는 [기술 감사 기록](../reports/comparable-project-audit-2026-10-15.json)에 있다.

이 조사는 유사 대회 11건과 반도체·제조 AI 기술을 현재 저장소에 대조한다. 실제 SK 해커톤 사이트, 개인 초대, 도구 허용과 공식 채점 조건은 다른 세션에서 대조한다. 아래 다른 대회의 문항, 배점, 포맷, 장비를 현 대회 요구사항으로 적용하지 않는다. 출처 31개 URL의 확인 범위는 [이번 출처 등록부](comparable-hackathon-sources.json)에 기록했다. 접근 실패 2건과 참가자 개인 구현 사례 1건을 포함한 수이며 독립적인 공식 근거 31개를 뜻하지 않는다.

## 준비 우선순위의 결론

이 저장소의 백엔드 개발자용 학습 목적에는 **문제 정의, 표와 문서의 독립 검산, 근거 표시, 실패 처리, 실제 실행의 재현**을 먼저 강화하는 방향이 적합하다. 이것은 아래 사례와 현재 코드의 공백을 연결한 판단이며 현 대회의 출제 예측이 아니다.

| 준비 단계 | 우선 작업 | 현재 활용할 자료 | 완료를 판단할 증거 |
| --- | --- | --- | --- |
| 개념과 자료 판단 | 정답 없이 풀고 숫자·조건·근거를 확인 | 선정20문항, RC01~RC03, 합성 CSV | 첫 시도, 풀이 시간, 검산과 수정 기록 |
| 업무용 AI 구현 | 반복 업무 하나와 입출력 계약을 정하고 기준 해법과 비교 | `examples/agent_loop.py`, 근거 카드 | 실제 모델 실행 결과, 여러 사례의 정확성·시간·실패 기록 |
| 모델 학습 구현 | 데이터 분할과 평가부터 고정한 뒤 기준 모델 학습 | 산업 배경 조사와 아래 데이터 후보 | 미사용 평가 자료, 재현 가능한 추론 명령, 지표와 오류 분석 |
| 시연과 전달 | 문제·입력·결과·효과·한계를 짧게 설명 | 기술 준비 체크리스트 | 새 환경 실행, 정상·어려운 사례 시연, 측정된 비교 결과 |

현재 예제의 도구 호출 구조를 이해하는 데 거대한 에이전트 프레임워크는 필요하지 않다. Anthropic은 고정 경로의 workflow와 모델이 경로를 고르는 agent를 구분하고, 지연·비용·성능을 보고 단순한 구성부터 시작하도록 설명한다. 이 원칙은 현재 표준 라이브러리 중심의 학습 세팅을 지지한다. [Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)

### 제조 업무용 에이전트

삼성전기의 2026년 10월 14일 발표는 10월 13~16일 해커톤의 주제를 반복 업무를 줄이고 실제 업무에 적용할 에이전트로 설명한다. 현업의 절차에서 해법을 구현하고 AI 활용과 적용성을 평가한다. 이 사례에서 가져올 준비는 “무엇이든 답하는 챗봇”보다 **누가, 어떤 자료로, 어떤 판단이나 기록을 반복하는지**를 좁히는 일이다. 현재의 규정 검토와 로그 계산 예제는 그 출발점으로 적합하다. 발표문에 나온 운영 계획을 기준일에 최종 수상 결과로 해석하지 않았다. [삼성전기 공식 발표](https://sem.samsung.com/kr/newsroom/news/view.do?id=10585)

Micron은 영상·음향·열영상 등 센서 AI와 업무 흐름을 조정하는 agentic AI를 제조에 연결한다. Samsung의 GTC 2026 발표도 장비 알람, 공정 제어, 수율 진단과 MES·디지털 트윈을 연결한다. 두 사례에서 전이할 것은 입력 자료와 실제 업무의 연결이다. 회사가 발표한 생산성 수치를 이 저장소의 예상 효과로 복사할 근거는 없다. [Micron 제조 AI 사례](https://www.micron.com/about/blog/applications/ai/smart-manufacturing-at-micron-ai-at-enterprise-scale), [Samsung GTC 2026 사례](https://semiconductor.samsung.com/news-events/tech-blog/samsung-showcases-agentic-ai-driven-semiconductor-engineering-innovation-at-nvidia-gtc-2026/)

### 반도체 비전과 Edge AI

IESA 브로슈어는 결함 6종 이상에 Clean과 Other를 추가해 최소 8클래스, 이미지 최소 500장, 학습·평가 분리, ONNX 모델과 전체 코드 등을 요구한다. eIQ 이식은 소프트웨어 산출물까지이며 하드웨어 보드 시연은 범위 밖이다. 데이터 구축부터 평가·이식까지 연결된다는 점이 핵심이다. 이 요구를 현재 프로젝트의 필수 GPU·CNN·8클래스 조건으로 옮길 수는 없다. [IESA 공식 브로슈어](https://i4c.in/wp-content/uploads/2026/01/DeepTech-Hackathon-Brochure-1-3.pdf), [운영기관 안내](https://i4c.in/iesa-hackathon/)

SEMICON India 2026의 KLA 문제는 노이즈와 낮은 해상도의 검사 이미지를 복원하며, 분포 밖의 이미지와 추론 속도도 다룬다. Applied Materials 문제는 반복적인 회로 패턴 안에서 기준 이미지의 위치를 찾고 좌표를 반환한다. 특히 평가자가 수정 없이 실행할 수 있는 추론 스크립트를 요구하고, 실패 사례도 제시하도록 안내한다. 현재 저장소의 새 환경 재현 검사와 입출력 계약 점검에 직접 참고할 만하다. 소개에 이전 행사 문구가 섞여 있어 구체적인 문제와 제출 요구를 우선했다. [SEMICON India 문제와 제출 안내](https://i4c.in/hackathon-2026)

DACON은 정상 학습 이미지 213장과 평가 이미지 100장을 제공한다. 제공된 학습 레이블은 정상이고 제출은 정상·비정상 이진 판별이다. Binary F1을 사용하며 공개·비공개 평가를 분리하고 상위 팀의 코드와 PPT도 검증한다. “정상 학습 자료만 있다”는 상황에서 일반 다중 결함 분류를 바로 설계하면 과제 정의부터 어긋날 수 있다. [데이터 설명](https://dacon.io/en/competitions/official/236224/data), [평가 규칙](https://dacon.io/competitions/open/236224/overview/rules)

### 공정 계획과 설비 상태

LG의 2020년 대회는 정해진 수요에 맞는 제조 계획을 CSV로 제출하는 과제다. 현재 RC01의 순이득, 시간, 비용, 라인 제약을 검산하는 연습은 계획 문제에 전이할 수 있다. 학습과 순수 최적화의 허용 범위를 따로 설명한 공식 Q&A 색인도 확인했으나 원문 직접 열람은 실패했다. 해당 제한은 그 대회의 조건으로만 보며 현재 사용할 알고리즘은 실제 규정 대조 결과를 따른다. [LG 제조 공정 대회](https://dacon.io/competitions/official/235612/overview/description), [공식 Q&A 확인 대상](https://dacon.io/competitions/official/235612/talkboard/400835?dtype=recent&page=1&ptype=pub)

PHM 2016 문제는 CMP 장비의 상태가 시간에 따라 변할 때 평균 재료 제거율을 예측한다. 최종 평가는 MSE 90%와 물리 기반 접근 설명 10%로 안내됐다. 센서 표만 잘 맞추는 것과 장비 상태를 물리적으로 설명하는 것은 별도 역량이라는 비교 사례다. 이 배점을 일반 산업 AI의 공통 채점표로 사용하지 않는다. [PHM 공식 문제](https://phmsociety.org/conference/annual-conference-of-the-phm-society/annual-conference-of-the-prognostics-and-health-management-society-2016/phm-data-challenge-4/)

DCASE 2026 Task 2는 정상 기계음, 미관측 기계와 환경 변화를 다루고, 올해는 거리별 2채널 녹음 조건을 추가했다. AUC와 오경보율이 낮은 구간의 pAUC 등을 조화평균해 평가한다. 시험 환경이 바뀌어도 견디는지와 오경보를 얼마나 만드는지를 별도로 볼 필요가 있다. URL에는 예전 first-shot 표현이 남아 있지만 실제 올해 문제 제목은 Noise-aware UASD다. [DCASE 2026 공식 과제](https://dcase.community/challenge2026/task-first-shot-unsupervised-anomalous-sound-detection-for-machine-condition-monitoring)

Bosch의 2016년 대회는 조립라인 측정으로 내부 불량을 예측하고 MCC로 평가한다. 제조 문제라고 정확도 하나를 공통 점수로 가정할 수 없다는 사례다. 공식 페이지의 색인 본문에서 목적과 지표를 확인했고 데이터 파일은 내려받지 않았다. [Bosch 공식 대회](https://www.kaggle.com/competitions/bosch-production-line-performance/overview)

### 시연 중심과 연구 중심 행사

HackZurich 2023은 실제 작동, 현실 문제와의 관련성, UX, 기술 구성과 문서, 발표를 함께 심사하고 2분 영상·발표를 안내했다. 이는 현재 코드에 짧은 시연과 전달 문서를 붙일 때 참고할 구조다. 2분이 현재 SK 대회의 발표 제한이라는 뜻은 아니다. [HackZurich 운영 페이지](https://hackzurich23.devpost.com/)

## 관련 기술에서 우선 익힐 일곱 주제

### 문제 정의와 기준 해법

업무를 해결할 때 먼저 사용자, 관측 가능한 입력, 원하는 출력, 제약, 완료 조건을 정한다. 예를 들어 “장비 로그를 요약”하는 일과 “현재 규정에 따라 점검 후보를 계산”하는 일은 다르다. 후자의 숫자 계산과 규칙 적용은 결정적인 함수로 처리하고, AI가 문서 선택과 설명을 담당하도록 설계할 수 있다. 고정 계산, 검색을 결합한 답변, 모델이 도구를 고르는 반복 구조를 같은 자료로 비교하면 AI를 추가한 이유를 설명할 수 있다. 이는 유사 사례를 현재 코드에 적용한 설계 권고다.

현재 `practice/core.py`는 Python과 SQLite를 교차 확인하며, `examples/agent_loop.py`는 세 도구와 호출 한도를 둔다. 이런 기반은 적절하다. 다만 기본 backend는 예정된 응답을 내는 `OfflineReplay`라서 “AI가 스스로 도구를 골라 풀었다”는 성과를 보여주지는 않는다. [에이전트 예제 안내](../examples/README.md)

### RAG의 근거와 문서 효력

RAG는 관련 자료를 찾는 단계와 그 자료로 답을 만드는 단계를 나누어 평가해야 한다. Ragas 논문도 관련 문맥 검색, 근거에 충실한 생성, 답변 품질을 구분한다. 현재 `validate_answer`는 근거 필드가 있는지 검사하지만 실제 문서가 주장을 뒷받침하는지는 판정하지 않는다. 제품으로 확장한다면 답변에 문서 ID·버전·효력 시각·대상 설비·원문 구절을 보존하고 상충 문서와 근거 부족 사례를 평가에 포함한다. [Ragas 원 논문](https://arxiv.org/abs/2309.15217)

RC02는 게시일과 효력일, 단위, 예외를 확인하는 좋은 연습이다. 다만 한 사례의 답을 외운 것과 새 문서 집합에서 맞는 근거를 찾는 것은 다르다. 처음 보는 변형 자료로 문서 선택과 최종 판단을 다시 확인해야 한다. [RC 과제 안내](../practice/readiness-guide.md)

### 드문 불량의 지표와 비용

다음은 직접 만든 수치 예다. 제품 10,000개 중 불량이 50개라면 전부 정상이라고 답해도 정확도는 99.5%지만 불량 재현율은 0%다. 다른 검출기가 불량 40개를 잡고 정상 160개를 오경보로 분류하면 재현율은 80%, 정밀도는 20%, F1은 0.32다. 검출 수 증가와 현장의 확인 부담을 함께 설명해야 한다.

| 판단 대상 | 먼저 볼 지표 | 함께 확인할 것 |
| --- | --- | --- |
| 불량을 놓치는가 | Recall, FN 개수 | 미검출 비용, 제품·설비별 결과 |
| 정상 제품을 너무 많이 의심하는가 | Precision, FP 개수 | 확인 작업과 생산 지연 비용 |
| 점수의 순위 품질이 좋은가 | ROC AUC, AP 등 | 양성 비율, 점수 분포, 적용 임계값 |
| 여러 결함 유형을 고르게 맞추는가 | 클래스별 Recall와 F1, Macro 평균 | 드문 클래스 표본 수, 혼동행렬 |
| 수치 예측이 맞는가 | 공식 회귀 지표 | 장비·기간별 오차와 실제 단위 |

scikit-learn은 AP와 선형 보간의 PR 곡선 면적을 구분한다. 보고서에는 “PR AUC”만 쓰기보다 계산 함수와 평균 방식을 적는 편이 재현에 유리하다. 현재 실제 대회의 공식 지표는 다른 세션에서 확정한 값을 우선한다. [평가 지표 공식 문서](https://scikit-learn.org/stable/modules/model_evaluation.html)

### 제조 데이터의 누수와 환경 변화

제조 데이터에는 같은 lot의 여러 관측, 같은 이미지의 회전·크롭, 이후 계측값과 조치 결과가 섞일 수 있다. 아래는 이 프로젝트에 적용할 분할 설계 권고다.

| 누수 또는 평가 문제 | 잘못된 예 | 검증할 방법 |
| --- | --- | --- |
| 같은 생산 묶음 공유 | 같은 lot의 센서를 학습·평가 양쪽에 배치 | 원본 묶음을 분리하고 겹침 수 검사 |
| 이미지 파생본 공유 | 원본은 학습, 회전본은 평가 | 원본 단위 분할 후 학습에만 증강 |
| 미래 정보 사용 | 예측 후 얻는 검사·조치 결과를 입력에 사용 | 예측 시각과 특징 사용 가능 시각 비교 |
| 전처리 누수 | 전체 자료로 결측 대체·특징 선택 후 분할 | 먼저 분할하고 학습 부분에서만 fit |
| 설비와 시기 변화 | 임의 분할 점수를 새 설비 성능으로 설명 | 미래 기간 평가와 미관측 설비 평가를 목적별로 설계 |

공식 문서는 전처리와 특징 선택을 학습 부분에만 fit하고 Pipeline으로 관리하도록 안내한다. GroupKFold는 같은 그룹의 양쪽 배치를 막고 TimeSeriesSplit은 과거에서 미래를 평가하지만, 둘 중 하나가 그룹과 시간을 동시에 격리한다고 가정하면 안 된다. 장비 전이와 미래 예측이라는 목적을 먼저 정해야 한다. [데이터 누수 문서](https://scikit-learn.org/stable/common_pitfalls.html), [그룹과 시간 교차 검증](https://scikit-learn.org/stable/modules/cross_validation.html)

### 이상 탐지와 원인 분석

관리도는 시간에 따른 품질 특성과 관리한계를 관찰한다. NIST는 한계 안의 점들도 비무작위 패턴을 보이면 조사할 필요가 있다고 설명한다. 이상 점수나 임계값 초과는 조사 후보이지 특정 고장 원인의 증명이 아니다. 제품 종류, 레시피, 센서 상태, 정비와 시점을 함께 비교하고 추가 측정이나 파일럿으로 가설을 확인한다. [NIST 관리도 설명](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc31.htm)

현재 합성 CSV는 245행 중 232행을 받아들였고, 생산량으로 가중한 수율은 약 94.9656%로 Python과 SQLite가 일치했다. 이것은 오류 처리와 계산의 검증이다. 실제 공장의 고장 원인이나 모델의 일반화 성능에 대한 증거는 아니다. 데이터 생성 코드도 물리 공정 시뮬레이션이 아님을 명시한다. [합성 데이터 설명](../data/synthetic/README.md), [저장된 기준 계산](../reports/lab-result.json)

### 최적화와 효과 설명

RC01의 목표는 불량 감소 수만 늘리는 것이 아니라 회피 손실에서 시험 비용을 뺀 순이득을 최대화하는 것이다. 기준 풀이의 A2·B3 조합은 비용 25만원과 5시간으로 기대 순이득 71만원을 만든다. 선택 개수가 적어도 제약과 목적함수에 맞으면 더 좋은 계획이 될 수 있다. 실제 적용 효과를 말할 때는 예상값과 실측값, 퍼센트포인트와 상대 변화율을 구분한다. 이 숫자는 직접 만든 연습 자료이며 대회의 산업 성과가 아니다. [창작 과제와 기준 풀이](../practice/readiness-cases.json)

업무 AI의 효과는 동일한 자료·산출물에서 사람 또는 규칙 기준의 시간과 정확도를 먼저 재고 비교한다. “LLM을 사용했다”, “문서가 많다”, “에이전트가 여러 개다”는 성과 지표가 되지 않는다. 문제에 맞는 지표, 작동 결과와 전달을 함께 보는 비교 대회의 구성을 현재 프로젝트에 적용한 권고다.

학습된 모델을 가지고 있다는 것, ONNX 변환이 된다는 것, 대상 장치에서 정확한 출력과 지연을 얻었다는 것은 각각 별도 증거다. [NXP eIQ 공식 설명](https://www.nxp.com/design/design-center/software/eiq-ai-development-environment/eiq-toolkit-for-end-to-end-model-development-and-deployment:EIQ-TOOLKIT)

### 수정한 실행 결함

`scripts/build_laptop_kit.py`는 `git`이라는 명령이 PATH에서 발견된다고 가정했다. 현재 PC에는 Git이 설치되어 있지만 PATH에는 없어 실제 실행에서 `FileNotFoundError`가 발생했다. 수정 후에는 PATH의 Git, 설치된 Codex 번들 Git, 사용자가 지정한 `--git-path`를 사용할 수 있다. 잘못된 명시 경로와 Git 부재는 복구 안내와 함께 내보내기 전에 실패한다.

학습 환경과 ZIP 생성은 의존성이 다르다. 공부·퀴즈·CSV·검증에는 표준 Python만 필요하고, 커밋된 HEAD에서 이동용 ZIP을 생성하는 저작 작업에는 Git이 필요하다. 시스템 PATH를 변경하거나 새로운 패키지를 설치하지 않았다.

현재 작업 폴더에는 이 조사와 코드 수정의 미커밋 변경이 있으므로 ZIP 생성기의 변경사항 커밋 요구는 유지된다. 재현 검사에서 만든 ZIP은 수정 전 커밋 `4e9eb5f`의 공개 자료다. 수정된 내보내기 함수를 별도 경로의 실제 깨끗한 커밋 트리에 실행했고, 새 가상환경을 생성해 그 자료를 검사한 뒤 수정한 코드 두 파일을 덧붙여 회귀 검사를 수행했다. 미커밋 변경을 몰래 ZIP에 포함한 결과가 아니다. 범위와 파일 목록은 [실행 감사 JSON](../reports/comparable-project-audit-2026-10-15.json)에 있다.

### 아직 완료라고 말할 수 없는 부분

현재 답변 검사는 JSON 형식·근거 필드 또는 고정 사례의 계약을 검사한다. 범용 답의 진실성, 잘못된 문서 선택, 새로운 규칙과 숫자에서의 성공률까지 판단하지 않는다. 여러 실제 모델 실행에서 근거와 결과를 평가해야 모델 신뢰성을 말할 수 있다.

Anthropic의 에이전트 평가 설명은 task·trial·grader를 구분하고 코드, 모델, 사람 판정을 조합한다. 여러 번의 실행과 실제 결과, 근거, 실패 이유를 따로 기록하는 접근이 현재 저장소의 다음 검증 단계에 맞는다. [에이전트 평가 공식 설명](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

표준 라이브러리 기반의 학습 목적에는 GPU, PyTorch, 벡터 DB, API 키, 서비스 화면, Docker가 없는 것이 결함은 아니다. 실제 모델 또는 서비스 과제가 확정되면 별도의 구현 환경에 필요한 의존성을 정한다. 지금 이들을 모두 설치하는 일보다 기존 자료로 독립 풀이를 완료하고 그 결과를 검증하는 것이 먼저다.
