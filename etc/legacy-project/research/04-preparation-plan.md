# 1차 예선과 후속 단계 준비 계획

10월 13일에 작성한 초기 계획이다. 현재 시작 순서와 실행 환경은 [학습 경로](../LEARNING-PATH.md)와 [환경 안내](../reports/local-status.md)를 따른다.

2026년 10월 13일 KST 기준. 신청 완료, 1차 예선 준비, 웹 개발 경험을 전제로 한다. 지금의 우선순위는 공식 체험으로 환경을 익히고, AI의 제안을 판단·검증하는 연습을 반복하는 것이다. 남은 시간에 새 모델 학습이나 복잡한 인프라를 시작하면 기본기 점검 시간이 줄어든다.

## 오늘 먼저 할 일

지원 내역과 개별 안내에서 예선 진출 여부 및 본인 배정일·시각을 확인한다. 신청 완료만으로 예선 진출을 단정하지 않는다. 다음으로 [프로그래머스 응시자용 공식 체험](https://programmers.co.kr/ai-assessment/preview)에 로그인해 지식평가와 활용평가를 경험한다. 체험의 문항 수·질문 횟수·감독 조건을 실제 SK 시험의 조건으로 옮기지 않는다. 세부 사실과 근거는 [대회 조사](01-event.md)에 정리했다.

로컬 창작 퀴즈 10문항으로 약점을 찾고, 틀린 이유를 `templates/study-log.csv`에 남긴다. 정답을 맞혀도 이유를 설명하지 못하면 복습 대상으로 둔다. 브라우저 기반 체험을 마친 후 데이터·문서 검증 미션을 하나씩 진행한다. 공식 체험의 문제당 AI 대화 사용 횟수는 초기화되지 않으므로 반복 학습은 다른 공개 샘플이나 로컬 창작 과제로 이어간다.

## 웹 개발 경험을 연결하는 방법

웹 개발에서 익숙한 요구사항·스키마·API·테스트를 AI 활용 문제에 연결한다. 입력을 이해하고 계약을 정한 뒤, 모델의 결과가 계약과 사실을 모두 만족하는지 따로 확인하면 된다.

| 웹 개발에서의 경험 | AI 문제에서의 적용 | 연습 |
| --- | --- | --- |
| API 입력 검증 | AI 입력의 누락·단위·자료 버전 확인 | 합성 CSV의 범위·중복 점검 |
| JSON 파싱과 타입 | 구문·스키마·의미 정확성을 각각 검증 | check-answer 이후 출처 수동 확인 |
| SQL 집계 | 분모·가중치·중복 조인의 영향 확인 | Python과 SQLite 수율 비교 |
| 디버깅과 테스트 | AI 생성 코드의 실패 재현과 반례 확인 | 주문 API 권한 검증 미션 |
| 검색과 캐시 | 오래된 자료·무관한 검색 결과 구별 | 현행 SOP와 폐기 SOP 구별 |
| 권한과 승인 | 모델 제안과 실제 실행을 구별 | 외부 메모의 명령문 처리 |

모델 이름과 프레임워크를 많이 외우는 것보다 한 과제에서 입력·계산·출처·예외를 끝까지 확인하는 연습이 웹 개발 경험을 잘 활용한다.

## 1차 전 학습 순서

1. 공식 체험의 화면과 AI 어시스트 사용 방식을 익힌다.
2. [AI 조사](02-ai-and-assessment.md)의 개념을 읽고 창작 퀴즈로 설명 능력을 점검한다.
3. 짧은 프롬프트에 목적·자료·제약·검증 요청을 넣는다.
4. AI 답의 수치를 계산하고 출처가 실제 주장을 지지하는지 확인한다.
5. [반도체 조사](03-semiconductor-and-projects.md)에서 제조 데이터와 메모리의 기본 흐름을 읽는다.

학습 시간의 약 80%를 플랫폼·AI·검증, 20% 이하를 도메인 배경에 사용하는 안을 권한다. 이 비율은 준비 전략이며 실제 시험 배점의 추정이 아니다.

## 2차 준비로 이어갈 일

1차 이후에는 합성 CSV 과제를 기준 풀이 없이 다시 풀고 데이터의 시간·장비·제품별 분할을 설명한다. 이어서 공개 데이터셋 하나로 기준 모델과 평가 지표를 정한다. 표본이 작고 피처가 많은 자료라면 복잡한 모델보다 단순한 기준 풀이와 누수 없는 검증을 먼저 만든다.

실전 도구가 확정되면 그 도구에 맞춰 입력 파일 읽기, 자료 요약, 결과 저장, 재실행을 연습한다. Cofa Probe의 공개 설명은 과정 기록과 사람의 판단을 준비하는 데 참고하되 실제 SK 미션의 제한·가중치는 개별 안내를 확인한다.

웹 개발자에게는 두 방향이 특히 실용적이다. 하나는 표 데이터를 분석하고 검증 가능한 결론을 내는 과제다. 다른 하나는 가상의 장비 로그와 버전이 있는 문서를 연결해 근거 있는 답변을 제공하는 과제다. 문서 검색 데모라면 문서 5개와 질문 10개로 시작하고, 최신 규정 선택·인용·모르는 질문 처리부터 검증한다.

## 본선 준비로 이어갈 일

미공개 과제를 미리 고정하기보다 공통 구조를 연습한다. 문제 정의, 자료 점검, 단순한 기준 풀이, 필요한 AI 기능, 독립 검증, 사람의 최종 판단 순서다. [반도체 사례와 프로젝트 후보](03-semiconductor-and-projects.md)에서 현장 연결이 분명한 후보 하나를 골라 3분 설명을 준비한다.

설명에는 누가 어떤 결정을 해야 하는지, 지금의 기준 결과는 무엇인지, AI가 어느 단계에 도움을 줬는지, 실패할 때 어떻게 드러나는지, 효과를 어떤 지표로 재현하는지를 포함한다. 산업적 효과를 합성 데이터의 결과만으로 실제 생산 개선 수치라고 표현하지 않는다.

## 10월 13일 초기 세팅과 추가 개발 환경

초기 환경은 Python 3.9.13 가상환경, Python 표준 라이브러리의 CSV·JSON·SQLite, 기존 Node.js 22.17.0과 uv 0.11.19다. 이 조사에서 작성한 도구는 외부 Python 패키지·네트워크·모델 API 없이 실행된다. 실제 실행 결과는 `reports/environment.json`과 `reports/verification.json`에 남긴다.

가상환경의 실행 파일을 직접 호출하면 PowerShell 활성화 스크립트 없이 실행할 수 있다. 가상환경을 다른 경로로 복사하기보다 새 위치에서 재생성한다. [Python venv 공식 문서](https://docs.python.org/3/library/venv.html), [uv 환경 공식 문서](https://docs.astral.sh/uv/pip/environments/).

Python 3.9는 지원이 종료된 버전이므로 현재 환경은 이 폴더의 오프라인 연습에 사용한다. 2차·본선용 장기 개발에는 참가 플랫폼과 필요한 라이브러리에 맞는 지원 중인 Python을 별도 가상환경으로 준비한다. 예선 직전 기존 시스템 Python을 교체할 필요는 없다. 지원 상태는 [Python 개발 가이드의 버전 상태](https://devguide.python.org/versions/)를 참고한다.

데이터 분석을 확장한다면 pandas·scikit-learn·시각화 라이브러리가 후보가 된다. 문서 검색을 확장한다면 문서 처리와 검색 및 평가 기능이 먼저다. 실제 과제와 환경이 정해진 뒤 필요한 패키지를 작은 목록으로 고정하고 다시 실행해본다. GPU, 클라우드, 다중 에이전트 프레임워크는 현재 로컬 연습의 필수 요소가 아니다.

## 문의 초안

다음은 필요한 항목을 묶은 초안이며 발송하지 않았다. 이미 개별 안내에 답이 있으면 그 안내를 사용한다.

```text
SK하이닉스 AI 해커톤 2026 1차 예선 응시 예정자입니다.
개별 안내에서 확인되지 않은 응시 조건을 문의드립니다.

1. 본인 배정 시작 시각, 입장 마감 및 시험 길이
2. 시험 내 어시스트 외 AI·검색·메모·로컬 코드 사용 가능 범위
3. 브라우저, 카메라, 화면 공유와 신분 확인 조건
4. 사전 작성 자료 사용 및 문제당 AI 질문 제한
5. 연결 장애 발생 시 재접속과 답안 저장·제출 절차

확인 부탁드립니다.
```

연락처와 실제 공개 규정은 [대회 조사](01-event.md)에 있다. 문제나 실제 답안을 문의 메일에 붙여 넣지 않는다.
