# 유사 대회에서 가져온 기술 준비 체크리스트

2026년 10월 15일 KST. 이 목록은 사전 연습과 향후 구현을 위한 권고이며 실제 SK 대회 요구사항이나 채점표가 아니다. [비교 조사](../research/12-comparable-hackathons-and-technical-audit.md)의 근거와 조건을 함께 읽는다. 개인 수행 결과를 적을 때는 이 파일을 `data/private/`로 복사한다.

## 학습 환경

- [ ] `scripts/study.ps1 -Mode check` 또는 지원 Python의 `scripts/study.py --mode check`가 통과한다.
- [ ] 다른 위치로 복사한 뒤 가상환경을 새로 만들고 같은 점검을 통과한다.
- [ ] 최소지식 PDF와 원문이 맞는 버전인지 확인한다.
- [ ] 이동용 ZIP을 만들 때 공개 변경사항을 먼저 커밋한다. ZIP은 커밋된 HEAD만 담는다.
- [ ] Git이 PATH에 없으면 설치된 번들 Git 자동 탐색 또는 `scripts/build_laptop_kit.py --git-path 'Git 실행파일 경로'`를 사용한다.

## 개념과 자료 판단

- [ ] 정답을 보지 않고 선정 20문항을 풀고, 틀린 이유를 보기 없이 설명한다.
- [ ] RC01에서 순이득 최대화, 생산량 가중 비율, 제약을 별도로 검산한다.
- [ ] RC02에서 게시 시각과 효력 시각, MB와 MiB, 결측과 경계값을 구분한다.
- [ ] RC03에서 AI 보고서의 숫자 오류, 설명과 원인 확정의 차이를 확인한다.
- [ ] 이미 본 답을 기억한 결과와 새로운 자료의 첫 풀이를 구분해 기록한다.
- [ ] 수행 시간, 질문, 독립 검산, 수정 전후 답을 개인 기록에 남긴다.

## AI 결과물을 구현할 때

- [ ] 대상 사용자, 반복 업무 하나, 입력과 출력, 완료 조건을 한 문단으로 정한다.
- [ ] 규칙 또는 SQL로 풀 수 있는 기준 해법과 AI 해법을 같은 입력으로 비교한다.
- [ ] 문서 근거는 문서 ID, 버전, 효력 시각, 설비 범위, 실제 인용 구절을 보존한다.
- [ ] 계산은 결정적인 함수로 검산한다. JSON 형식 검사와 내용 진실성 판정을 구분한다.
- [ ] 정상, 상충 문서, 결측, 단위, 예외, 근거 부족 등 별도의 평가 자료를 둔다.
- [ ] 모델, 프롬프트, 자료와 도구 버전, 실행 결과, 실패 이유를 기록한다.
- [ ] 여러 번 실행해 성공률과 변동을 확인하고, 처리 시간과 호출 수를 함께 측정한다.
- [ ] 오프라인 재생을 실제 모델 추론으로 표시하지 않는다.
- [ ] 같은 작업의 사람 또는 규칙 기준 시간과 정확도를 측정한 뒤 효과를 주장한다.

## 모델 학습 과제일 때

- [ ] 데이터 원본, 레이블 의미, 라이선스와 외부 데이터 허용 조건을 확인한다.
- [ ] 예측 시점에 사용 가능한 특징만 사용한다.
- [ ] 학습과 평가에 같은 lot 또는 원본 이미지의 파생본이 섞이지 않게 한다.
- [ ] 미래 예측과 미관측 설비 평가를 목적에 맞게 따로 설계한다.
- [ ] 전처리, 결측 처리, 특징 선택, 임계값 선택에 테스트 정답을 사용하지 않는다.
- [ ] 공식 지표 외에도 불량 미검출과 오경보의 개수 및 비용을 확인한다.
- [ ] 추론 명령이 입력 경로와 출력 경로를 받아 새 환경에서 수정 없이 실행된다.
- [ ] 모델 파일만으로 배포 성공을 주장하지 않고 실제 대상 런타임 결과를 기록한다.

## 시연과 제출물

- [ ] 정상 입력 한 개와 어려운 입력 한 개에서 입력부터 결과까지 보여준다.
- [ ] 실패 사례와 근거 부족 사례도 설명한다.
- [ ] README에 실행 명령, 입력 형식, 출력 형식, 데이터와 모델 출처를 적는다.
- [ ] 실제 시험의 외부 도구와 제출 조건은 공식 정보 대조 세션에서 확정한 값을 적용한다.

2분 시연, 평가 자료 수, 모델 포맷 등은 비교 대상 대회에서 얻은 준비 아이디어다. 이 목록을 전부 완료해야 현 예선에 응시할 수 있다는 뜻은 아니다.
