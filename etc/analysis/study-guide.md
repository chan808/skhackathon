# 사진 같은 지식 문제와 AI 활용 문제를 준비하는 공부법

2026년 10월 15일. AI 지식이 적은 백엔드 개발자를 위한 학습 문서다. 예상 출제표가 아니라 공개 체험과 제공된 사진에 맞춘 준비 순서다. 실제 문제의 정답 번호를 외우기보다 개념·조건·검증을 설명하는 것을 목표로 한다.

## 사진의 유형이 문서에 있는가

있다. [기존 샘플 분석의 지식1·2번](preview-analysis.md#지식-10문항의-독립-풀이)이 텍스트 생성의 확률적 예측과 텍스트·이미지 기능을 다룬다. 다만 해설표만으로 처음 배우기에는 설명이 짧아 이 문서를 추가했다. 사진의 오른쪽이 잘려 모든 보기를 다시 확인한 것은 아니다.

사진은 모델을 직접 구현하는 문제가 아니라 **기능·한계·입출력을 업무 상황에 맞게 판단하는 문제**다. 보관된 [최소지식 문서](../legacy-project/MINIMUM-KNOWLEDGE.md)는 토큰·RAG·평가를 보충할 때 사용한다. 이 문서가 그 책에서 짧게 다루거나 빠진 모달리티·편향·합성 데이터 등의 입문 설명을 보완한다.

## 먼저 이해할 두 가지

### 텍스트 생성은 자연스러운 문장을 만드는 일과 사실 확인을 구분한다

LLM은 문맥을 바탕으로 다음 **토큰**을 예측해 텍스트를 생성한다. 토큰은 단어 전체·일부·문자 등에 대응하며 단어와 항상 같지 않다. 보고서 작성·요약·번역에 사용할 수 있지만 생성 내용의 사실성을 자동으로 보장하지 않는다. 정확한 업무 수치는 실제 조회 결과나 제공 자료에 대조해야 한다. [Google 언어모델 입문](https://developers.google.com/machine-learning/crash-course/llm)

백엔드에서 JSON 응답의 형식이 맞아도 필드 값이 틀릴 수 있는 것과 같다. 자연스러운 문장과 정확한 답은 별도 조건이다.

### 모달리티는 정보의 형태다

텍스트·이미지·음성 같은 형태를 모달리티라고 부른다. 문서 요약은 보통 텍스트→텍스트, 텍스트 설명으로 그림을 만드는 기능은 텍스트→이미지다. 한 서비스가 여러 기능을 제공할 수 있지만 그것이 단일 모델·동일 알고리즘이라는 뜻은 아니다. 이미지 생성 전체를 기존 그림의 단순 복사나 정확한 현실 재현으로 설명하지 않는다.

보기에서는 ‘어떤 정보를 받아 어떤 정보를 내보내는가’를 먼저 찾는다. API가 JSON과 파일 업로드·다운로드를 함께 지원할 수 있는 것처럼 서비스와 개별 처리 모델을 구분한다.

## 우선 익힐 10개 주제

한 행씩 읽고 가린 뒤, 오른쪽 질문에 자기 말로 답한다. 정답 번호를 기억하는 것만으로 완료하지 않는다.

| 주제 | 알아야 할 내용과 업무 예 | 스스로 설명할 질문 |
| --- | --- | --- |
| 생성형 AI·환각 | 그럴듯한 출력에도 없는 사실이 섞일 수 있다. 생성과 DB의 실제 조회를 구분한다 | 존재하지 않는 장애 로그를 인용하면 무엇으로 확인할까? |
| 모달리티 | 텍스트·이미지·음성은 정보 형태다. 같은 서비스에 여러 입출력이 있을 수 있다 | 문서 요약과 그림 생성의 입력·출력은 무엇인가? |
| 프롬프트 조건 | 목표·대상·처리 규칙·출력 형식을 명확히 한다. 조건 하나만 잘 지켜도 전체 성공은 아니다 | 역할과 JSON 형식은 맞지만 집계 기간이 틀렸다면? |
| 편향·공정성 | 데이터와 질문·평가 기준에 편향이 생길 수 있다. 대상에 맞춘 개인화만으로 공정성이 증명되지 않는다 | 국적에 따라 면접 질문을 바꾸는 것만으로 충분한가? |
| 합성 데이터 | 인공적으로 만든 데이터도 분포·원문 재현·성능을 검증한다. 합성이라는 이름만으로 안전·동등성을 보장하지 않는다 | 가상 고객 데이터로만 테스트했을 때 놓칠 것은? |
| 이용 조건·권리 | 도구 이용 조건과 생성물의 사용 가능성을 별도로 확인한다. 상업 이용 가능 표기만으로 타인의 권리 문제까지 해결됐다고 보지 않는다 | 로고를 쓸 수 있다는 서비스 표기 외에 무엇을 검토할까? |
| RAG·문서 시점 | 검색한 자료를 문맥에 넣고 답한다. 높은 유사도는 현행 규정의 증거가 아니다. 날짜·버전·대상을 확인한다 | 폐기된 문서가 검색1위면 어느 단계를 고칠까? |
| 필드 매핑·파이프라인 | 입력·외부 응답·변환·템플릿을 단계별로 추적한다. 연결 오류를 프롬프트만으로 고치려 하지 않는다 | `order_total`과 `total`의 연결 누락을 어떻게 찾을까? |
| XAI·설명 | 모델 예측에 기여한 특징 등을 설명하려는 방법이다. 별도 AI의 자연스러운 설명이 실제 예측 근거를 입증하지는 않는다 | 설명을 만들 때 어떤 모델·입력·출력을 연결해야 할까? |
| 가명·익명 | 이름을 코드로 바꿔도 추가 정보로 연결될 수 있다. 위험 감소와 익명화를 같은 것으로 보지 않는다 | 고객ID 치환만으로 식별 위험이 없어졌다고 할 수 있을까? |

가명·익명·합성 데이터의 용어 차이는 [ICO 용어집](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-sharing/anonymisation/glossary)과 [가명 처리 설명](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/data-sharing/anonymisation/pseudonymisation)을 참고했다. 이는 용어 학습이며 특정 서비스의 적법성이나 한국 법령의 세부 요건을 판정한 자료가 아니다.

## 객관식은 조건을 통과하는지 검사한다

요청이 ‘최근7일 자료만 사용하고, 결측치를 규칙대로 처리하고, JSON으로 출력’이라면 다음 세 조건을 검사한다.

```text
기간이 맞음 AND 결측 처리 규칙이 맞음 AND 출력 형식이 맞음
```

보기를 읽을 때 다음 순서로 판단한다.

1. 지문이 요구한 목표·조건을 짧게 나열한다.
2. 보기의 모든 절을 읽고 개념 오류·조건 누락·근거 없는 단정을 찾는다.
3. 한 절이라도 틀리면 그 보기를 제외한다.
4. 남은 보기의 원인과 해결책이 직접 연결되는지 확인한다.

‘항상·자동·완벽’ 같은 표현은 검토할 단서다. 그 단어가 있다는 이유만으로 오답이라고 외우지 않는다. 보기 번호 대신 **왜 맞고 다른 설명은 왜 틀리는지** 한 문장씩 말한다.

### 자기 점검: 자체 제작한 짧은 상황

아래는 공식 문제의 복제나 기출이 아닌 연습이다. 먼저 답하고 아래 해설과 비교한다.

1. 요약 문장에 원문에 없는 매출 수치가 들어갔다. 문장이 자연스러우면 받아들여도 되는가?
2. 문서 요약과 이미지 생성을 제공하는 한 앱은 반드시 하나의 모델·동일 알고리즘을 사용하는가?
3. 응답 형식은 JSON이지만 최근7일 대신 한 달을 집계했다. 요구사항을 충족했는가?
4. 구버전 운영 문서가 유사도1위다. 유사도 점수만 더 높게 요구하면 버전 문제가 해결되는가?
5. API 필드 연결이 빠져 보고서가 비었다. 먼저 프롬프트를 길게 바꿀까, 입력→변환→템플릿 값을 추적할까?
6. 합성 주문 데이터로 테스트가 통과했다. 실제 주문 분포와 경계값 테스트는 생략할 수 있는가?

**해설:** 1은 원문 대조가 필요하다. 2는 여러 모델을 연결한 서비스일 수도 있어 단정할 수 없다. 3은 기간 조건 위반이다. 4는 날짜·버전·대상 메타데이터와 선택 기준을 점검해야 한다. 5는 연결 경로를 추적한다. 6은 실제 분포·경계 사례에 적용되는지 별도 검증한다. 모두 같은 답을 외우는 대신 조건을 바꾼 반례를 하나씩 만든다.

## 저수준 AI를 쓰는 시험인가

**낮은 성능의 AI를 쓴다고 확정한 근거는 없다.** 공식 FAQ는 체험과 실제 모델의 응답 품질이 다를 수 있다고 설명한다. 공식 제품 설명에서 확인되는 것은 질문 횟수·대기·지문 복사 등의 제한과 과정·결과 평가다. [공식 체험 FAQ](https://programmers.co.kr/ai-assessment/preview), [공식 평가 설명](https://programmers.co.kr/ai-assessment/insight/why-we-built-ai-assessment)

따라서 준비 목표는 **제한된 AI 도구에 필요한 자료를 전달하고 결과를 검증하는 것**으로 잡는다. 질문 제한이 있는 것과 모델 성능이 낮은 것은 다르다. 파이썬으로 저수준 모델을 구현하거나 새 에이전트를 만드는 것이 필수라는 뜻도 아니다. SK 공식 안내는1차를 기초 지식과 활용 검증으로 소개하며 세부 설정은 개인 초대를 따른다. [공식 대회](https://skhynix-hackathon.com/ai-2026)

활용 연습에서는 다음 다섯 단계를 직접 수행한다.

1. **사람이 조건 정리:** 대상·기간·분모·단위·예외·출력 형식을 먼저 적는다.
2. **필요한 자료 선택:** 원문 열람과 AI 첨부 상태를 구분한다.
3. **구체적인 작업 요청:** 추출·계산·조건 판정·근거 표를 요청한다.
4. **독립 검산:** 숫자 하나와 규칙 하나 이상을 원문·허용된 계산 방법으로 확인한다.
5. **최종 답 작성:** AI 채팅과 답안 입력은 별개다. 요구 형식과 제출 상태를 확인한다.

연습 요청의 예는 ‘이 자료에서 대상ID별 최신 상태를 추출하고, 조건별 충족 여부와 근거를 표로 보여줘. 누락은 추측하지 마’다. 후속 질문은 실제 오류를 특정한다. 일반적인 ‘다시 검토’보다 ‘기준일 이후 기록이 포함됐다. 해당 행을 제외하고 차이를 보여줘’처럼 범위를 좁힌다.

사진 유형에 우선 필요한 것은 기능·한계·조건 판별과 자료 검증이다. 역전파 수식·GPU 최적화·새 프레임워크는 이 기본기를 익힌 뒤 확장한다. 학습 우선순위이며 실제 출제 제외를 뜻하지 않는다. 공개 체험의 정답 번호 암기나 임의의 연습 점수를 합격선으로 사용하지 않는다.

이 문서 작성으로 로그인 후 전체 원자료 재검증이 완료된 것은 아니다. 그 진행 상태는 [샘플 재점검 기록](preview-analysis.md#재점검-상태와-전체-자료-완료-기준)을 따른다.
