# 프로그래머스 응시자 체험 상세 분석

2026년 10월 14일 조사. **이 URL은 예선 대비에 관련성이 높은 프로그래머스 공식 응시자 체험이다.** 이번에 공개 소개와 공식 연결 데모의 자료 선택·질문·답안 흐름을 확인했다. SK 전용 모의시험이라는 근거는 없으며 개인 초대의 설정이 우선한다.

## 대회와 어떤 관계인가

프로그래머스 공식 제품 소개가 해당 URL을 응시자 체험으로 직접 연결한다. SK 공식 대회 페이지는 1차에서 AI 기초 지식·활용을 검증한다고 안내하고 Programmers를 파트너로 표시한다. 사용자 초대의 플랫폼명과도 일치하므로 첫 연습 장소로 적절하다. [프로그래머스 제품 소개](https://programmers.co.kr/ai-assessment), [공식 체험](https://programmers.co.kr/ai-assessment/preview), [SK 공식 대회](https://skhynix-hackathon.com/ai-2026)

| 구분 | 확인되는 범위 | 확인되지 않는 범위 |
| --- | --- | --- |
| 공개 응시자 체험 | 자료·AI·답안 인터페이스를 익힐 공식 경로 | SK 실제 문항·합격선·출제 비중 |
| 제품 소개·안내 데모 | 평가 목적과 대표적인 조작 흐름 | 참가자별 AI 모델·횟수·토큰·시간·배점 |
| 본인 초대 | 안내에 표시된 일정·문항·제한 시간 | 표시되지 않은 외부 도구·감독·복구 조건 |
| 초대된 사전 테스트 | 제공된 범위의 접속·장치 확인 | 일반 공개 체험으로 대체 완료했다는 판단 |

20문항·30분을 지식, 16문항·90분을 활용으로 대비하는 것은 학습 가설이다. 아직 초대에서 영역명을 확인한 것은 아니다.

## 세 종류의 평가를 어떻게 준비할까

공식 제품은 지식·활용·전문평가를 구분한다. 지식은 기본 원리와 리터러시의 객·주관식, 활용은 과제와 프롬프팅, 전문은 직무 프로젝트 등으로 확장된다. 평가 조합과 운영 옵션은 기업이 정한다. [공식 평가 유형](https://programmers.co.kr/ai-assessment)

준비 배분은 다음을 권한다. 아래 학습 선택은 공식 출제 예측이 아니다.

| 순서 | 먼저 할 것 | 백엔드 경험과 연결 |
| --- | --- | --- |
| 1 | 최소지식 여섯 블록과 선정20문항 | 입력·상태·오류·검증의 용어를 AI에 연결 |
| 2 | 활용 자료형 과제와 공식 체험 | 요구 해석, 집계·조건·단위 검산, 정확한 출력 |
| 3 | 전문 사례에서 익숙한 API 오류 과제 | 정상·경계·실패 입력과 원인 구분 |
| 이후 | 새 agent 앱·프레임워크 제작 | 예선 기본 연습이 끝난 뒤 확장 |

앞선 10월 13~14일 공개 화면 관찰 기록에는 지식10문항, 활용의 설문·비용·규정 사례 각4문항, 전문의 교육 효과·API 오류 사례 각1문항이 있었다. **이번 재조사에서는 로그인 후 전체 체험 목록이나 풀이를 새로 검증하지 않았다.** 이전 목록은 연습 방향의 참고로만 쓰고 현재 본인 화면에서 다시 확인한다. [이전 공개 목록 조사](01-event.md)

## 공개 데모에서 새로 확인한 핵심

[공식 제품에 연결된 안내 데모](https://demo.arcade.software/b5dk0zn4GHjoXFKsAmpP?embed=&embed_desktop=inline&embed_mobile=inline&show_copy_link=true)의 공개 설명·이미지를 읽었다. 사용자의 실제 체험 세션을 조작하거나 질문 횟수를 사용하지 않았다.

| 화면·흐름 | 확인한 내용 | 연습에서 확인할 것 |
| --- | --- | --- |
| 왼쪽 목록 | 문제 번호와 공통 지문 묶음 | 먼저 하위 문항을 훑어 필요한 자료 범위 파악 |
| 중앙 자료 | 여러 PDF와 파일별 토큰량 | 원문 열람과 AI 전달 상태를 따로 확인 |
| 문제 선택 | AI 패널의 `문제`에서 질문 대상 지정 | 현재 풀이 대상이 맞는지 확인 |
| 파일 전달 | `AI 질문에 추가` 후 `첨부 파일`에서 관리 | 필요한 규정·대상 자료가 함께 포함됐는지 확인 |
| 입력·마감 | AI 대화와 답안 입력칸, 종료 버튼 구분 | 답 형식과 최종 제출·완료 상태 확인 |

예시에서는 첨부5개가 19,009/20,000토큰으로 표시되고 AI 대화는 10회 남음으로 표시된다. **이 수치는 해당 데모의 표시값이다.** 모델 전체 문맥이 20,000이라는 뜻도, SK에서 각 문항마다10회 또는 전체160회를 준다는 뜻도 아니다. 개별 문항·자료 묶음 중 어디에 카운터가 적용되는지는 본인 화면에서 확인한다.

파일을 읽는 창에서 보았다고 AI에 전달됐다고 생각하면 안 된다. 반대로 여러 자료를 모두 전달하면 질문 대상과 관계없는 맥락이 늘어날 수 있다. 실제 체험에서 선택 상태를 확인하는 것이 좋다.

## 제한된 AI 질문이 평가 준비를 바꾸는 이유

10월 7일 공식 설명은 질문 횟수 제한, 응답 도출까지30초 대기, 지문 그대로의 복사 제한, 자료 첨부, 과정과 결과의 평가를 소개한다. 기업별 조합에 따라 문항 수와 시간이 달라진다고 한다. **SK의 실제 설정은 아직 확정하지 않는다.** [공식 평가 설명](https://programmers.co.kr/ai-assessment/insight/why-we-built-ai-assessment)

이에 따른 준비 권고는 다음과 같다.

- 질문 전: 목표·대상·기간·조건·요구 출력 형식을 먼저 파악한다.
- 첫 질문: 필요한 자료와 판단 기준을 함께 전달한다.
- 검증 질문: 발견한 수치·규칙 오류를 구체적으로 지정한다.
- 최종 답: AI의 긴 설명과 답안 입력 형식을 구분한다.

과정 평가가 있다고 해서 질문 수를 채우거나 검증했다고 말만 쓰는 연습은 권하지 않는다. 실제로 확인한 원문·계산·오류 수정이 자신의 판단 근거가 되어야 한다. 미공개 채점표의 점수를 늘리는 요령으로 보장할 수는 없다.

질문에 대기 시간이 있으면 반복 호출이 검산과 답안 작성 시간을 줄일 수 있다. 응답을 기다리는 동안 원문·단위·요구 형식을 확인하는 연습을 한다. 대기 중 문항 전환이나 동시 요청의 지원 여부는 직접 체험에서 확인한다.

## 많은 문항을 풀 때 사용할 작업 방식

90분/16문항은 평균5분37.5초다. 공통 자료의 첫 독해와 후속 문항 풀이 시간이 같을 필요는 없다. 실제 묶음 수와 재방문 허용을 보고 시간 배분을 조정한다.

1. 하위 질문의 대상과 답 형식을 먼저 적는다.
2. 공통 기준을 작은 표로 만든다: 자료ID / 효력일 / 대상 / 조건 / 단위 / 예외.
3. 대상 자료만 연결하고 필요한 판단을 요청한다.
4. AI 답의 핵심 주장 두 개를 원문 또는 독립 계산으로 확인한다.
5. 요구된 코드·숫자·문장만 답안 형식에 맞게 입력한다.
6. 미응답·저장·제출 상태를 마지막에 확인한다.

검증할 대표 오류는 AND/OR 조건 누락, 특정 지역·시점의 기준 혼동, 평균의 평균, 분모 변경, 단위·퍼센트포인트 혼동, 원문에 없는 근거다. 승인 표시 하나만 보고 모든 조건을 만족한다고 판단하지 않는다. 이는 자료형 연습에 사용할 일반 점검 항목이며 공식 문제의 정답 공개가 아니다.

## 백엔드 개발자에게 맞는 첫 연습

공식 체험의 질문을 쓰기 전에 [자체 RC02](../practice/readiness-guide.md)를 먼저 한 번 끝낸다. 이 폴더의 질문 기록 명령은 AI를 호출하지 않으므로 실제 앱이나 내장 Assist의 반응은 별도로 경험해야 한다.

```powershell
py -3 scripts/study.py --mode case --case RC02
```

다음은 자체 합성 자료용 질문 예시다. 공식 데모 질문·정답을 복사한 것이 아니다.

```text
목표: 제공된 자료에서 조건을 만족하는 대상 ID를 찾기.
적용 시점·대상·문서 우선순위·단위·예외를 먼저 정리해줘.
각 후보를 조건별 표로 비교하고 결론마다 자료 ID를 제시해줘.
자료에 없는 사항은 미확정으로 표시해줘.
```

후속 질문은 “다시 확인” 대신 실제 발견한 문제를 지정한다. 예를 들어 “분모에 제외 행이 포함됐다. 동일 기준으로 다시 집계하고 차이를 설명해줘”처럼 입력·출력·검증 대상을 명확히 한다.

공식 체험에서는 이 사고 틀을 유지하되 화면이 지원하는 문제·파일 선택과 허용 입력 방식을 따른다. 복사 제한을 OCR·자동화로 우회하는 준비를 하지 않는다.

## 오늘 노트북에서 할 60분

| 시간 | 수행 | 남길 증거 |
| --- | --- | --- |
| 0~10분 | 로그인·목록·문제·자료·AI·답안 위치 파악 | 선택 상태와 카운터 범위 확인 |
| 10~35분 | 활용 사례 하나, 실제 질문 전에 스스로 조건 정리 | 첫 질문·핵심 검산·최종 답 형식 |
| 35~50분 | 지식 체험 또는 자체 선정20의 약점 복습 | 헷갈린 용어와 오답 이유 |
| 50~60분 | 자기 풀이 검토와 환경 기록 | 자료 누락·AI 오류·조작 시간 |

이 배분은 연습 제안이다. 무료 체험의 질문을 가볍게 소모하지 말고, 현재 FAQ의 횟수와 초기화 정책부터 읽는다. [개인 기록 양식](../templates/preview-session.md)을 `data/private/`에 복사해 작성한다.

ChatGPT 설치는 학습과 합성 자료 검증에 유용하다. 실전이 제공하는 Assist 사용법과 외부 ChatGPT 허용 여부는 별개다. 이 링크만으로 해외·VPN·감독 조건도 확인할 수 없다. [노트북·현지 회선 안내](../LAPTOP-PREPARATION.md)

## 조사 범위와 한계

이번에는 공식 제품·10월7일 설명·SK 공개 페이지를 새로 읽고, 공식 연결 데모의 공개 설명 및 정적 이미지로 화면 흐름을 확인했다. 현재 자동 본문 추출에서는 preview의 메뉴와 체험용 연결만 나오며 동적 목록·FAQ가 완전히 추출되지 않았다. 연결된 브라우저가 없어 실시간 UI를 새로 조작하지 못했다.

앞선 같은 날짜의 공개 FAQ 확인 기록에는 PC 전용, 시간·화상 감독 없음, 대화 제한·초기화 불가, 별도 체험 결과 리포트 미제공이 있다. 이는 [이전 확인 기록](07-notice-and-open-questions.md)이며 이번 실시간 재확인 결과로 표시하지 않는다. 안내 데모의 리포트 소개는 제품 예시로 해석하고 무료 체험에서 리포트를 받을 수 있다고 약속하지 않는다.

로그인 후 실제 샘플 풀이·채점·저장·새로고침·재접속 동작과 개인 시험은 수행하지 않았다. 현재 문제 목록·카운터·FAQ는 노트북에서 본인이 확인하고 실제 응시 설정은 운영자 안내로 확정한다.
