# 두 세션에 맞춘 1차 학습과 시간 배분

2026년 10월 14일 기준. 초대 안내에 **20문항·30분과 16문항·90분**이 나왔다면 짧은 개념 판단과 자료 활용·검증을 함께 연습한다. 이 문서는 해당 구성에 대응하는 학습안이며 모든 참가자의 시험 설정을 공개 공지로 확인했다는 뜻은 아니다. 개인 날짜·시간·원본 초대 이미지는 Git에서 제외한다.

## 확인된 구성과 아직 모르는 것

초대 캡처에서 문항 수와 제한 시간을 확인할 수 있다. 문항 유형, 평가 명칭, AI Assist의 상세 제한, 외부 AI·검색·코드·메모 허용, 감독, 재방문·저장·제출 방식은 해당 화면만으로 확정할 수 없다.

프로그래머스는 지식·활용·전문 평가를 구분하며 조합과 시간은 기업별로 달라진다고 설명한다. 공개 체험은 개념 문제와 자료 분석·비용·규정 과제를 제공한다. 이를 근거로 짧은 세션을 개념, 긴 세션을 활용 중심으로 준비하는 것은 합리적인 학습 전략이지만 실제 세션 명칭과 문항 형식의 확인을 대신하지 않는다. [공식 평가 설명](https://programmers.co.kr/ai-assessment/insight/why-we-built-ai-assessment), [공식 체험](https://programmers.co.kr/ai-assessment/preview).

## 20문항 30분 연습

평균 90초다. 그러나 모든 문제에 90초씩 쓰면 검토·제출 시간이 없다. 이미 아는 개념을 빠르게 판단하고, 보기의 조건과 오류를 짧게 설명하는 훈련을 한다.

| 구간 | 자체 연습 배분 | 할 일 |
| --- | --- | --- |
| 첫 풀이 | 22분 | 목표·용어·분모·조건을 읽고 답 선택 |
| 검토 | 5분 | 불확실한 답과 단위·예외·계산 다시 확인 |
| 저장과 제출 확인 | 3분 | 미응답·요구 형식·최종 제출 상태 확인 |

이는 시간 전략이며 화면 이동·답 변경이 가능하다고 가정한 학습안이다. 실제 플랫폼에서 재방문이 안 되면 남은 시간에 맞춰 한 번에 판단한다. 보기 없이 설명하지 못하는 개념은 정답 번호 암기로 넘기지 않는다.

처음에는 시간 제한 없이 선정 20문항의 해설을 읽는다. 두 번째부터 30분 예산으로 진행한다.

```powershell
.\.venv-study\Scripts\python.exe -m practice quiz --bank backend --count 20
.\.venv-study\Scripts\python.exe -m practice quiz --bank backend --count 20 --exam --minutes 30 --seed 18
```

`backend`는 기존 기초 17개와 심화 3개를 조합한 자체 선정이다. 전체 문제 수 76개에서 선택하므로 새 기출 20문항을 추가한 것이 아니다. 문항별 소요 시간, 총시간, 예산 초과, 오답을 기록한다. 타이머는 입력을 강제 종료하지 않으며 공식 시험의 종료 동작을 재현하지 않는다. 기록의 bank를 이용해 오답 복습도 가능하다.

## 16문항 90분 연습

평균 5분 37.5초지만 자료를 처음 읽는 시간과 최종 검토를 따로 확보한다. 실전 문항이 같은 자료를 공유하면 해당 자료의 기간·단위·현행 규정·집계 기준을 한 번 정리해 재사용한다. 16개가 각각 독립적인 큰 개발 과제라고 가정하지 않는다. 실제 자료 묶음과 화면 구조는 공식 체험·해당 시험 안내에서 확인한다.

권장 과정은 목적 확인 → 자료 선택 → 계산·근거 정리 → 필요한 AI 질문 → 독립 검증 → 요구 형식의 답 작성이다. 긴 프롬프트 하나보다 지금 불확실한 조건을 해결할 질문을 만든다.

예시 질문:

> 제공한 자료에서 적용 시점·대상·단위·분모·예외를 먼저 정리해줘. 결론마다 문서 ID와 계산식을 적고, 자료에 없는 사항은 확인 불가로 표시해줘.

> 위 결론의 틀릴 가능성을 점검해줘. 같은 숫자를 반복하지 말고, 원래 분모·단위·문서 효력일·경계값으로 검산해줘.

독립 확인에서는 계산기·코드가 허용되지 않더라도 표본 손계산과 원문 대조를 할 수 있다. 실제 시험에서 사용할 도구는 안내에 맞춘다. 플랫폼 일반 설명의 질문 제한과 대기 시간을 자기 시험에 그대로 적용하지 않는다.

## 기존 사례를 묶는 90분 훈련

기존 RC01·RC02·RC03은 총 13개 작업이며 실제 16문항을 재현한 자료가 아니다. 숫자를 억지로 맞추지 않고 서로 다른 검증 능력을 함께 훈련한다.

| 구간 | 시간 | 확인할 능력 |
| --- | --- | --- |
| 전체 조건 읽기 | 5분 | 목표·자료·답안 요구 정리 |
| RC01 | 25분 | 비용 제약·최적 조합·가중 비율 |
| RC02 | 20분 | 문서 효력·단위·연속 조건·승인 상태 |
| RC03 | 30분 | 지표·누수·비용·인과 주장 검토 |
| 자기 답 검토 | 10분 | 숫자·근거·예외·확인 불가·저장 |
| 합계 | 90분 | 다른 자료에도 원리 적용 |

90분 안에는 기준 풀이를 열지 않는다. 종료 후 별도 시간으로 자가 평가한다. `/prompt`는 질문 기록이며 실제 AI 호출이 아니다. 공식 AI 응답 속도와 화면 조작은 공개 체험에서 추가로 확인한다.

```powershell
.\.venv-study\Scripts\python.exe -m practice.readiness start --case RC01 --minutes 25
.\.venv-study\Scripts\python.exe -m practice.readiness start --case RC02 --minutes 20
.\.venv-study\Scripts\python.exe -m practice.readiness start --case RC03 --minutes 30
```

## 백엔드 개발자가 먼저 배울 것

1. Token·context·temperature·embedding: 처리 한계·유사도·사실성을 구분한다.
2. Prompt·RAG·fine-tuning: 입력 조정·근거 검색·가중치 학습을 구분한다.
3. Structured output·tool calling: 형식·호출 요청·실행 결과·업무 성공을 구분한다.
4. Precision·recall·비용·threshold: accuracy 하나보다 목표에 맞는 지표를 선택한다.
5. Train·validation·test·누수: 예측 시점에 없는 정보와 반복 평가를 찾아낸다.
6. 비율·가중치·시간·단위·문서 효력: 직접 계산과 근거 대조로 결론을 검증한다.

모델 구조·미분·CNN·LoRA·MoE·HBM의 심화는 이 기본기를 설명하고 적용할 수 있게 된 뒤 확장한다. 학습 순서이지 미출제 선언이 아니다. [백엔드와 AI 연결 노트](10-backend-ai-bridge.md), [기초 커리큘럼](08-ai-foundations-curriculum.md).

## 에이전트 제작 해커톤에서 옮겨갈 경험

에이전트 앱에는 하네스·파이프라인·테스트·권한 같은 실행 기반이 필요하다. 고정 workflow와 모델이 동적으로 행동을 선택하는 agent는 제어 위치가 다르다. 선택이 모호할수록 근거·실패 사례·비용·반복 종료를 평가해야 한다. [Anthropic 공식 설계 설명](https://www.anthropic.com/engineering/building-effective-agents).

이전 대회에서 코드를 만들었다는 경험은 요구사항을 나누고 실행·오류를 추적하는 데 옮겨간다. 이번 1차에서는 개인의 짧은 문항 처리·자료 판독·판단 검증·플랫폼 입력을 우선 연습한다. 이전 순위만으로 현재의 지식 수준이나 실패 원인을 판정하지 않는다. 직접 앱을 만드는 것과 AI 답을 판단하는 것은 관련되지만 서로 다른 연습이 필요하다.

## 4일 계획

| 순서 | 약 2~3시간의 목표 | 남길 증거 |
| --- | --- | --- |
| 첫날 | 연결 노트·최우선 개념·선정20문항·공식 체험 | 보기 없는 설명과 오답 이유 |
| 둘째 날 | 30분 풀이·RC01·RC02·취약 개념 | 문항 시간·단위·효력·제약 검증 |
| 셋째 날 | RC03·심화 핵심·별도 자료 적용 | 누수·잘못된 인과·비용 오류 수정 |
| 전날 | 30분 풀이와 90분 통합훈련·환경 확인 | 첫 답과 수정 기록·미확정 규칙 정리 |

전날에 새 프레임워크를 설치하거나 실제 모델 학습을 시작하는 것을 기본 목표로 두지 않는다. 예산이 더 적으면 핵심 개념·공식 체험·낯선 사례의 독립 검증을 먼저 한다. 임의 정답률을 대회 합격선으로 해석하지 않는다.
