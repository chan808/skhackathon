# AI 활용과 검증 연습 과제

모든 과제는 이 폴더를 위해 만든 비공식 연습이다. 실제 시험 형식·시간·점수와 연결하지 않는다. 공식 공개 체험을 먼저 경험하고 부족한 부분을 아래 과제로 보완한다.

## 제한된 질문으로 문제 해결

연습 시간은 25분, AI 질문은 3회로 스스로 제한한다. 실제 대회의 제한 횟수라는 뜻은 아니다. `data/synthetic/lots.csv`의 전체 수율과 오류 처리 정책을 설명하는 것이 목표다.

첫 질문 전 3분 동안 목적, 사용할 필드, 수율 공식, 데이터 품질 검사를 적는다. 첫 질문은 계산 접근법과 실패 조건을 요청한다. 두 번째 질문은 자신의 계산이나 코드의 반례를 검토하게 한다. 세 번째 질문은 확인된 수치와 근거만 넣어 답변을 다듬는 데 쓴다. AI가 파일을 직접 읽지 못하는 환경에서는 읽었다고 가정하지 말고 필요한 스키마와 작은 샘플을 제공한다.

완료 조건은 수치 재현, Python과 SQL의 교차 확인, 제외 레코드 설명, 근거 없는 원인 확정 방지다. 사용할 AI가 없다면 가상의 응답에 아래 오류를 직접 넣고 찾아낸다.

## 잘못된 데이터 분석 고치기

다음은 의도적으로 잘못 만든 주장이다. 공식 자료의 인용이 아니다.

> 전체 수율은 각 로트 수율의 평균이다. 양품 수가 비어 있으면 0으로 채운다. 중복 로트도 측정 횟수이므로 합산한다. E3의 수율이 낮으니 E3가 모든 불량의 원인이다.

45분 안에 네 주장 각각에 대해 문제점, 수정 원칙, 검증 방법을 적는다. 장비별로 제품 구성이 같지 않을 때 결론이 바뀔 수 있다는 반례도 제시한다. 참고 풀이를 실행한 뒤 자신의 결과가 다르면 계산식과 제외 정책부터 비교한다.

## 근거 있는 문서 답변

`evidence-cards.json`의 `documents`와 `tasks`만 읽고 20분 안에 답한다. `answer_key`는 끝난 뒤 확인한다. 문서 날짜, 폐기 여부, 온도 단위, 연속 측정 조건, 외부 문서의 명령문을 점검한다.

최종 답변은 결론, 수치 계산, 문서 ID, 한계의 순서로 작성한다. `templates/answer.example.json`을 참고해 JSON으로 저장하면 구조 검사를 실행할 수 있다. 구조 검사는 근거가 실제로 주장을 뒷받침하는지 자동 평가하지 않는다.

```powershell
.\.venv-study\Scripts\python.exe -m practice check-answer templates\answer.example.json
```

## 웹 개발자의 코드 검증

가상의 주문 조회 API가 `GET /orders?user_id=...`로 전체 주문을 반환한다. AI가 제안한 수정은 `user_id` 필터 추가뿐이다. 30분 안에 인증 사용자와 쿼리 사용자의 일치 여부, 권한 검증, 빈 결과, 페이지네이션, SQL 파라미터 바인딩을 점검한다. 테스트에는 타인의 주문 접근, 정상 조회, 없는 사용자, 특수문자, 중복 주문을 포함한다.

자신이 이해하지 못하는 코드를 제출하기보다 실패 상황을 재현하고 최소 수정의 효과를 설명하는 연습이다. 실제 고객 정보와 운영 서비스 없이 가상의 레코드 5개로 진행한다.

## AI 개념을 설명하는 연습

1분씩 말로 설명한다. 토큰과 단어의 차이, 낮은 temperature가 사실을 보장하지 않는 이유, 검색과 답변 평가를 나누는 이유, 임베딩 유사도가 진실성을 뜻하지 않는 이유, 도구 호출 제안과 실제 실행의 차이, 테스트 데이터로 전처리를 학습하면 안 되는 이유다. 정의를 외운 뒤 자신의 웹 서비스 사례로 연결한다.
